# スタックちゃん ホスト Windows版

0.5.0-preview.1 / 2026-10-21。PCのホットスポットへ接続した端末を信頼して、自動で受け付けます。4行コードの入力は不要です。

## 初回

1. PCをインターネットへ接続し、Windowsのモバイルホットスポットを2.4GHzで有効にします。接続機器がいないと自動停止する省電力設定があれば無効にします。
2. 端末の画面ボタンを押しながらリセットしてWi-Fi設定へ入り、スマホをStackchan-Setup（パスワード12345678）へ接続します。ブラウザの192.168.4.1で、PCホットスポットと同じネットワーク名・パスワードを設定します。
3. StackchanHost.exeを起動し、接続方式を「Wi-Fi（USB不要）」にします。「再検出」でPCのホットスポット側アドレスを選びます。候補が空ならホットスポットの稼働を確認してください。
4. Gemini APIキーとモデルを確認し、「接続して開始」を押します。端末コードの入力や端末登録の操作はありません。
5. 「ホットスポット上の端末が接続しました」と出たら端末を短押しして起こし、登録した呼びかけをします。開始音の終了から約0.7秒後に質問します。

## 接続と信頼の範囲

ホットスポットのWi-Fiパスワードを知って接続できる機器を信頼する方式です。音声通信はホットスポットのWi-Fi暗号化で保護し、アプリ独自のTLS・登録コード・Bearer認証は使いません。ホストはホットスポット側IPv4だけで待ち受け、同じサブネット内の接続元だけを受け付けます。上流の共有Wi-Fi全体を受付先にはしません。APIキーはPCからGeminiへの通信だけに使い、端末へ渡しません。

端末はDHCPゲートウェイのTCP48443へ接続します。IPの固定や毎回のUSB設定転送は不要です。ホストは停止するまで稼働します。Windowsの受信許可が必要な場合はホットスポット側だけに限定してください。

## 次回以降

ホットスポットとホストを起動すれば、保存済みWi-Fiに接続してサービスへ自動接続します。Gemini APIキーは保存を選んだ場合だけWindowsユーザー専用に暗号化保存し、未選択なら今回の起動中だけ使用します。旧版のpairing.jsonと端末の旧ペアリング情報は使用せず、そのまま保持します。

## 手動質問・呼びかけ登録

起きた状態で画面ボタンを約2秒押し、Release to askで離すと手動質問できます。開始音の終了から約0.7秒後に発話します。
呼びかけを再登録する場合は、スリープ状態から5〜6秒押して離します。短押し→開始音終了→約0.7秒後に同じ呼びかけ、を3回行います。3回の整合確認と保存に成功すると登録を置き換えます。途中の取消・失敗では旧登録を保持します。10秒長押しでPCコードを更新する旧操作は廃止しました。

## USB診断と確認範囲

「USB診断（従来）」は開発用の別経路で、約10分で終了します。同時に別ツールでUSBポートを開くことはできません。
Gemini問い合わせ失敗時は、キーや会話本文を表示せず、認証・利用制限・モデル・通信などの分類を表示します。
実機での新方式の自動接続・会話・再起動後復帰はVALIDATION.mdに記載した結果を参照してください。PC上の模擬往復は実機の合格とは区別します。
