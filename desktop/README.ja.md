# スタックちゃん ホスト Windows版

0.7.0 / 2026-10-25。「スタックチャン接続」で、ホスト待受と必要な初回Wi-Fi設定を開始します。有線PCで、候補版の設定引継ぎ・保存済み接続・AP自動設定・手動質問の回答音声/口パク/待受復帰を利用者確認済みです。正式版は同じ接続処理を使用します。端末ファームウェアは従来の0.6.0-rc.1のままで更新不要です。

## 日本語の声を最初に確認する

通常の「声（日本語・採用済み）」には、利用者が日本語の品質を確認して採用した声だけが並びます。初回は空です。既存のAPIキーとWi-Fi設定は保持しますが、声は自動採用しません。

1. モデルは現在の対応候補であるgemini-3.8-liveを指定し、Gemini APIキーとPCホットスポットの接続先を確認します。
2. 端末をSleepingにし、「声を確認・管理」を開きます。試聴用の「端末をSleepingにしました」にチェックします。このチェックは端末状態の自動検知ではありません。
3. 評価候補を選び「候補の日本語サンプルを聴く」を押します。Gemini APIを使用して同じ短い日本語文を生成し、PCの現在の標準再生先から再生します。選択するだけではAPI送信や再生をしません。「試聴を停止」で中止できます。
4. 最後まで試聴し、発音・数字の読み・明瞭さ・安定性が適切なら「日本語に適する：採用」を押します。採用した声は通常のプルダウンへ即時追加され、その場で選択・保存されます。端末での確認操作は不要です。
5. 不適切なら該当する判定理由を選んで「日本語に適さない：除外」を押します。

通常リストで声を選ぶと保存され、次の質問から反映されます。声の変更だけでホスト停止や端末再接続は不要です。速度・ピッチの調整機能はありません。評価済みの声はモデル・カタログ版ごとに管理します。別モデルや候補一覧の改訂では再評価が必要になることがあります。

試聴中は端末をSleepingにしてください。端末の質問接続が届いた場合は試聴と同時に処理せず案内します。ただし、現行端末が録音を始める前の状態はホストだけでは取得できません。

評価候補Kore/Puck/Aoede/Charon/Fenrir/Zephyrは日本語合格済み一覧ではありません。PC試聴と利用者の採用操作によって通常一覧に加わります。サンプル音声・会話本文・APIキーは評価記録へ保存しません。Windowsの音量・再生先は自動変更しません。

## 初回

1. PCをインターネットへ接続し、Windowsのモバイルホットスポットを2.4GHzで有効にします。接続機器がいないと自動停止する省電力設定があれば無効にします。
2. StackchanHost.exeを起動します。接続方式はWi-Fi固定です。ホットスポット側アドレスが1件なら自動選択します。複数なら選択し、候補が空ならホットスポットの稼働を確認してください。
3. 初回設定が必要な端末は、既存操作（画面ボタンを押しながらリセット）でWiFi setup / Stackchan-Setupを表示させます。保存済みWi-Fiで接続できる場合、この操作は不要です。
4. Gemini APIキー・モデル・採用済みの声を確認し、「スタックチャン接続」を押します。声が空の場合は上の手順で確認してください。先にPC側で待ち受け、約10秒後も端末到達が未確認なら設定APを調べます。対応構成ではPCが一時接続してホットスポット情報を送り、20秒待機してPCのWi-Fiを元へ戻します。スマホ・端末コード入力は不要です。
5. 「ホットスポット上の端末が接続しました」と出たら端末を短押しして起こし、登録した呼びかけをします。開始音の終了から約0.7秒後に質問します。

初回の自動設定は、**有線インターネット接続、Wi-Fiアダプタ1台が未接続、2.4GHz/WPA2ホットスポット、同名設定APが1台**の構成が対象です。PCのWi-Fiを上流として使う場合、自動切替を行いません。従来のスマホ設定は引き続き利用できます。既にホットスポットへ参加した端末の待受には、この初回設定用の制約はありません。

「停止」やウィンドウ終了を押すと、送信前なら中止します。送信済みなら20秒の待機とPC復帰を終えてから終了します。端末に保存した設定は取り消しません。応答不明・到達未確認の場合は自動再送せず待受を継続します。PCホットスポットのアドレスが変わった場合は停止して「再検出」し、接続し直してください。Wi-Fi接続情報を画面・ログ・設定ファイルへ保存しません。

WindowsのWi-Fi/位置情報アクセスが拒否される場合は案内に従いWindows設定を確認してください。同じSSID・既存のAPパスワードでは個体認証はできないため、設定対象以外の端末APは停止してください。アプリ強制終了やOS障害までPCの復帰を保証するものではありません。

## 接続と信頼の範囲

ホットスポットのWi-Fiパスワードを知って接続できる機器を信頼する方式です。音声通信はホットスポットのWi-Fi暗号化で保護し、アプリ独自のTLS・登録コード・Bearer認証は使いません。ホストはホットスポット側IPv4だけで待ち受け、同じサブネット内の接続元だけを受け付けます。上流の共有Wi-Fi全体を受付先にはしません。APIキーはPCからGeminiへの通信だけに使い、端末へ渡しません。

端末はDHCPゲートウェイのTCP48443へ接続します。IPの固定や毎回のUSB設定転送は不要です。ホストは停止するまで稼働します。Windowsの受信許可が必要な場合はホットスポット側だけに限定してください。

## 次回以降

ホットスポットとホストを起動すれば、保存済みWi-Fiに接続してサービスへ自動接続します。Gemini APIキーは保存を選んだ場合だけWindowsユーザー専用に暗号化保存し、未選択なら今回の起動中だけ使用します。旧版のpairing.jsonと端末の旧ペアリング情報は使用せず、そのまま保持します。

## 手動質問・呼びかけ登録

起きた状態で画面ボタンを約2秒押し、Release to askで離すと手動質問できます。開始音の終了から約0.7秒後に発話します。
呼びかけを再登録する場合は、スリープ状態から5〜6秒押して離します。短押し→開始音終了→約0.7秒後に同じ呼びかけ、を3回行います。3回の整合確認と保存に成功すると登録を置き換えます。途中の取消・失敗では旧登録を保持します。10秒長押しでPCコードを更新する旧操作は廃止しました。

## 確認範囲

ホストアプリはWi-Fi専用です。USB診断の接続方式・ポート欄は表示しません。
Gemini問い合わせ失敗時は、キーや会話本文を表示せず、認証・利用制限・モデル・通信などの分類を表示します。
実機確認は、有線PCの候補版での基本操作です。反復成功率、長時間運用、通常再起動後の一連の復帰、別PC・上流Wi-Fi構成、声変更/PC試聴の新版での実機再評価は未検証です。PC上の模擬往復・正式版EXEの自己診断は実機の合格とは区別します。
