版: R03 / 更新日: 2026-10-19（日本時間）
対象: M5AtomS3R + Atomic Voice Base A149、Arduino / PlatformIO、COM4。
案件ルート: `C:\Users\thoma\SynologyDrive\H\Doc\Src\Codex\projects\ai-stackchan\AI_StackChan_Ex\Stackchan-chatgpt`。
目的: 顔と短い案内で動作状態を区別し、登録した呼びかけから音声質問へ進む。既存の1質問1回答・16kHz入力/24kHz出力を維持する。

## 合意した最終仕様

スリープ（マイク停止）→ボタン→ウェイク／呼びかけ待ち（端末内だけで検出）→ウェイクワード→受付合図→質問受付／リスニング→末尾無音で録音終了→送信→シンキング→回答受信→スピーキング→残響待ち→呼びかけ待ち。

質問終了から回答の実再生終了・残響待ち完了までは、ウェイクワードを含む音声入力を受け付けない。再生中の声による割込みは実装しない。ボタンによる中止は可能にする。次の質問にも毎回ウェイクワードを必要とし、履歴を伴う複数ターンとは区別する。

- 最初は1つの登録済みパターンを統合し、その後3〜5回の登録・別発話による検証へ進む。MFCC/DTWによる特徴比較であり、ニューラルモデル追加学習・話者認証ではない。
- 登録と検出は端末内で行う。新登録と検証が成功するまで旧パターンを保持する。再登録は専用画面へ分離する。
- 呼びかけと質問は続けて話さず、受付合図を待つ。呼びかけ前の音声はクラウドへ送らない。
- 無発話、取消、雑音過大は短い案内後に呼びかけ待ちへ戻る。PC/Wi-Fi切断は顔の状態とは別に表示し、質問受付を止める。
- 呼びかけ待ちが3分続いたら自動スリープ。初期はUSB・通信を維持する休止で、深い省電力スリープではない。手動質問の救済操作も残す。
- 誤検出回数・検出率・検出遅延を、距離、声量、似た語、周囲会話、テレビ、回答の再生後に分けて測る。少数回の成功を精度保証としない。

## 第1段階の実装

`include/DeviceMode.h`に18モードと自動スリープ・マイク許可条件を定義した。`FaceUI.h` / `src/FaceUI.cpp`は独自の目・口の図形描画で、画像素材や新たな顔ライブラリは追加していない。[Stack-chan](https://github.com/stack-chan/stack-chan)の顔表示を参考に、現在のM5GFXへ合わせた。依存はM5Unified 0.2.26 / M5GFX 0.2.33、Espressif32 6.11.0 / Arduino-ESP32 2.0.17。既存の固定依存はplatformio.ini / server/package-lock.jsonを参照。

| 内部モード | 表示・役割 |
|---|---|
| Boot / Connecting | 起動とWi-Fi接続、点の移動 |
| Sleep / Waking / WakeWait | 閉眼・小さな呼吸動作、開眼、瞬き。第1段階のWakeWaitは手動受付のみ |
| Armed / Preparing / Listening | ボタンを離す案内、閉眼して環境音測定、発話受付と音量バー |
| Sending / Thinking / Receiving | 視線と点の移動、送信・回答待ち・受信の短い表示 |
| Speaking / Cooldown | 実再生中の簡易口パク、再生後の待機 |
| Notice / Error | 無発話・取消・雑音などの案内、困り顔と短い原因 |
| Enrolling / Verify / Setup | 後続段階用の表示定義。操作・録音登録はまだ実装していない |

画面下の接続表示は、未設定・Wi-Fi切断・PC停止・PCオンラインを区別する。顔用スプライトは一度だけPSRAMへ確保（128×128×16bitで32,768 bytes）。通常描画は最大20fps、状態変化時は即時描画。録音のcallbackからは描画せず、前景処理で描画する。確保失敗時は文字表示へ退避する。

現段階の口パクは音声内容に同期せず、実再生中に周期的に動く。スピーカー停止検出後は口パクを止める。開始音は既存の0.5秒処理を使い、その間のアニメーションは更新しない。色・英語案内・顔の形・動きの好みは実機表示で確認する。

### 現段階の操作

1. 起動直後はSleeping。画面ボタンの短押しで開眼し、Readyへ進む。**この段階ではウェイクワードを検出しない。** 画面はHold: manual askと表示する。
2. Readyで短押しするとスリープへ戻る。長押し2秒でRelease to recordの案内→離す→開始音→約1秒静かに待つ→Listening / Speak nowの表示後に質問する。
3. スリープ中に長押ししても、その操作はウェイクだけに使う。同じ操作で録音を始めない。
4. 録音・通信・再生中の押下で中止。離す操作が続いても、新たな録音やスリープ切替には使わない。
5. Readyの無操作3分でマイク停止のスリープへ戻る。第1段階では180,000msのビルド時定数。接続の稼働通知だけでは無操作時間をリセットしない。
6. 成功後はマイク停止のまま300ms待ってReadyへ戻る。残響待ち300msは暫定で、ウェイク検出を統合する第2段階に実機調整する。

PC起動は既存のStart-Gemini-Device.cmd。サービスは引き続き最長約10分で終了する。新旧ファームウェアで操作が違うため、起動メッセージに両方の操作を併記した。
