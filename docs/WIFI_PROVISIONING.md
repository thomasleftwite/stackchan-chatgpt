# Gemini端末版のWi-Fi設定と開発方針

2026-10-20。Stage3 R07にWiFiManager 2.0.17を統合。

## 操作

- 通常起動時に保存済みWi-Fiへ接続する。未設定・接続失敗なら設定APを時間制限なしで開く。
- 再設定は画面ボタンを押したままリセットして起動する。起動したら画面ボタンを離す。リセットボタンとは別。
- スマートフォンでStackchan-Setupへ接続し、固定パスワード12345678を入力。自動表示されなければブラウザーで192.168.4.1を開き、2.4GHz Wi-Fiを設定する。
- PCは同じLANなら5GHzでもよい。ゲスト/端末分離されたネットワークは使わない。
- 保存後はPCホストの接続して開始を実行する。接続に失敗しても設定APを維持し、再入力できる。
- 既存のWi-Fi情報を先に消去しない。設定パスワードは端末画面だけに表示しUSBへ出力しない。音声登録・SPIFFSを初期化しない。

## 機能を積み上げる方針

確認済みのWi-Fi設定・登録・顔表示・会話機能は通常ファームウェアで維持する。
単体診断専用のビルドは通常版とは区別する。検証のため通常版から機能を外す必要がある場合、依存関係や競合の理由と復元方針を利用者に説明する。

通常の音声通信はWi-Fi、補足の診断はUSBとする。USB診断経路は維持する。
現時点ではPC接続先/一時トークンの通知と稼働通知もUSBに依存するため、USB不要の通常動作は未完成。制御のWi-Fi移行は次工程。
Wi-Fi障害時はネットワーク診断も使えないので、USBの復旧/診断経路を残す。

## 検証

Wi-Fi保存済み/未接続/強制APのホスト回帰をwifi-uiとして追加。端末ビルドと実機AP・設定保存・再起動後再接続はそれぞれ区別して記録する。
ホストソースにWi-Fi失敗の専用表示を追加。既存配布EXEには未反映で、再生成が必要。

## Android切断の報告と無期限化（2026-10-20）

標準のtzapu/WiFiManager 2.0.17を継続使用。ライブラリ実装でsetConfigPortalTimeout(0)が時間制限を無効化することを確認して適用。画面もNo timeoutへ変更。
setBreakAfterConfig(false)でルーター接続失敗後も設定をやり直せるようにした。
USBへ固定イベントAP_JOIN/AP_LEAVE/AP_STOPだけを出し、スマホ側の離脱とAP自体の停止を区別する。SSID/PW/MACは出さない。設定AP中はブロッキング処理のため通常のGEM INFO処理は設定終了後に再開するが、Wi-Fiイベント診断は設定中も利用可能。

## 設定完了後の状態照会（2026-10-20）

利用者がWiFiManager設定完了を報告。COM4のGEM INFOでGEM STATE configured=0 wifi=1 pc=0を確認。端末のWi-Fi接続は成立。PCホストの設定/接続は未成立。端末自体の外部DNS/HTTP疎通は現ファームウェアに照会手段がなく未検証で、wifi=1をインターネット到達の証明とはしない。現構成のGemini APIへのインターネット通信はPCホストが担当する。

## 中継準備失敗の切り分け（2026-10-20）

利用者の中継準備失敗を、配布EXEの展開済み同梱ランタイムで再現。保存LAN接続先が現在のPCアドレスと不一致。同じ保存キー/モデルで古い接続先はfailed/code1、現在のLAN接続先に置換するとready/preflight=true/code0。ダミー設定のfixture/geminiもready成功。同梱欠落やキー形式不備ではなく、当該再現は古いLANアドレスに起因。外部API呼出しなしなのでキーのGoogle側での有効性は未検証。
対処はホストの再検出で現在のLANアドレスを選び直す。アプリ起動後のネットワーク変更時に保存/選択済みアドレスが古くなり得る。キー・モデルは変更不要。秘密値は診断出力/本書へ記載しない。

## 接続後の動作チェック（2026-10-20）

利用者がホスト接続成功を報告。PC中継のLAN待受を確認し、healthzがHTTP200/status=ok/mode=gemini-live/protocolVersion=2。実際のWebSocket Upgradeで認証なし・誤った認証の両方が401拒否。初回のurllib検査はConnectionヘッダーが通常HTTP扱いとなり404で判定不能だったため、正規Upgradeで再検証した。
ホストがCOM4を使用しており、別プロセスの同時状態照会は利用不可。稼働中ホストを停止せず維持した。ホストUIの呼びかけ/回答再生完了と利用者の聴取・Ready復帰の確認待ち。追加の録音開始や合成音再生、Google API呼出しは診断側から行っていない。
