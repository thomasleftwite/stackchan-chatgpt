# 第3段階R03: 0.7秒待ちの維持と最後の判定の再照会

2026-10-19（日本時間）/ R03。対象: AtomS3R + Atomic Voice Base A149、Arduino-ESP32 2.0.17、PlatformIO atoms3r-gemini-device。目的: 登録準備のNOISY再発時に、短い表示やUSBログの取り逃しだけで原因が不明になる状態を改善する。R02の音声処理は変更せず、ビープ終了後700ms待ちを登録/照合の両録音で維持する。原因解明・実登録の成功は未完了。

## 再開後の実機結果

R02で無言試験1回はrms=94/threshold=750/gap=729ms、NO_SPEECHだった。しかし続く登録試験では、Setup（77,000ms）→Preparing/mic=1（80,750ms）→NOISY（81,766ms）→Sleep/mic=0（83,594ms）となり、改善が安定しているとは言えない。利用者はRepeat same callへ進まず、続けた短押しでスリープになったと報告。NOISYで既に登録が中断した後の通常切替で、照合・保存には到達していない。証跡.pio/device-check/face-stage3-r02-registration-20261019-r02.json。この回はCAL行を取得できず、実際の音量判定値は不明。ビープ残響以外も含め、発生源は未確定。

## 変更

- 最後の環境音判定の固定数値行と登録結果をRAMだけに保持し、GEM INFO/GEM PINGの応答で再取得できるようにした。起動時/新しい登録開始時はNONEへ戻す。音声/特徴量/秘密情報を保持・保存する機能ではなく、電源断で消える。
- GEM BUILD enrollment=3を出し、診断版の実行を識別する。protocol v2と既存の状態行は維持。
- 登録前のビープ完了→700msマイク停止→マイク起動→既存の初期0.4秒分破棄と0.6秒分の環境音測定、の順はR02と同じ。RMS/thresholdの判定値も変更しない。利用者からの0.7秒待ち維持の指示を反映。
- PC側の許可リストに固定ビルド番号とNONE状態を追加。任意の文字列/過大な数値/付加データは拒否する。監視側は状態種類ごとの差分だけを記録し、再照会による同じ結果の繰返しを抑える。

## 検証

雑音校正でNOISYにした後、最初のシリアル出力を破棄しGEM INFOで再取得するテストを先に追加。R02では失敗、R03で成功した。

- 登録UI14/14、録音品質10/10、FaceUI27/27、質問UI6/6、保存21/21、PC監視17/17、状態許可リスト2/2。今回合計97項目成功。
- 700ms待ちと、その待ち中の取消でマイクが起動しない回帰テストも維持。
- 端末版/通常版のビルド2/2成功。依存はplatformio.iniの固定版のまま。サーバ・共通ルール・表示デモは今回変更せず、今回の再実行範囲には含めない。

再現手順は[第3段階R02](WAKE_STAGE3_R02.md)と同じ。今回のホスト登録UI件数は14項目。実機では最初に診断版番号・Sleep/mic停止を確認し、無言試験1回のCAL/resultを後から再照会する。正常なら最初の呼びかけ録音を確認し、Try your callへ進んでから照合・明示保存を行う。NOISYが再発する間は後続操作を案内しない。

導入は委譲済み権限の範囲でCOM4/0x10000のアプリだけを更新する。SPIFFS/NVS/既存設定・登録は書き換えない。Googleへの送信は行わず、USB接触不良の原因究明保留も維持する。候補ハッシュ・書込み・起動結果は追記する。
