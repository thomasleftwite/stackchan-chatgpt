# ホスト接続ボタンへの組込み R01

2026-10-25 / ホスト候補0.7.0-rc.1 / `codex/host-ap-provisioning`。
基準コミット: `050e0f3`。仕様は[AP設定R01](HOST_AP_PROVISIONING_R01.md)、前段の実証は[Windows診断R01](HOST_AP_PROVISIONING_WINDOWS_PROBE_R01.md)。利用者の「新ボタンへの組込みを進める」指示に基づく。

## 実装した動作と対応範囲

- 「スタックチャン接続」でPCホットスポットIPv4を再検出する。候補1件なら古い保存アドレスからも自動更新し、複数候補なら利用者の選択を使う。Geminiキー・モデル・採用済みの声は既存方式を維持する。
- ホストを先にホットスポット側だけで待ち受ける。開始失敗なら端末設定へ進まない。約10秒の既存端末到達確認で接続通知があればAP設定を省略する。
- 初回AP設定の対応範囲は、実証した**有線インターネット、未接続の物理Wi-Fiアダプタ1台、2.4GHz/WPA2ホットスポット、設定APのBSSID1件**。他構成を自動切替しない。設定を見送った場合も既存端末の待受は継続する。
- 設定APへ一時接続し、対象インターフェースに割り当てられたAP側IPv4からだけフォームへアクセスする。プロキシ・リダイレクトを使わない。POSTフォームを確認し、接続先資格情報をURL本文に入れて1回だけ送る。クエリ・コマンドライン引数・ログ・設定JSONへ資格情報を出さない。
- 応答受付後は20秒間無線状態を維持してPCを元の未接続状態へ戻す。送信後の停止・終了要求でもこの待機と復帰を終えてから終了する。応答不明は自動再送しない。
- 保存応答・AP消失・接続台数だけで成功を表示しない。ホストのリモート側ヘルス要求、または有効なWebSocket接続を到達通知に使う。PC自身からの要求は通知しない。60秒で到達未確認ならその旨を表示し、待受を継続する。
- PCホットスポットの設定・アドレスが変化した場合は案内し、停止・再検出を求める。自動で別サブネットへ待受を広げない。変更されたアドレスへの自動再バインドは今回の対応外。
- 接続完了前のホスト経由試聴を抑止し、既存の試聴と新規接続開始も排他にする。端末到達後は既存の声変更・PC試聴を維持する。

## 新版の実機確認手順

1. 旧0.6.0-rc.1のEXEと今回の候補EXEを別フォルダで保持する。製品候補の自己診断成功後に切り替える。
2. 起動中の旧ホストを「停止」→終了する。ホットスポットと端末の電源は維持する。新旧ホストを同じポートで同時稼働させない。
3. 新EXEを起動し、保存済みのキー/声を確認して「スタックチャン接続」を押す。端末からの到達とPC Online/Sleepingを個別確認する。初回設定を検証する場合は、端末を既存操作で設定AP待機にする。
4. 初回設定は20秒維持とPC復帰後の到達まで待つ。停止/終了試験ではPCのWi-Fiが元へ戻ったことを確認する。成功後の通常再起動、会話/音声/口パク/待受復帰は別々に記録する。

同名APの偽装に対する個体認証、別PC/別ドライバ/上流Wi-Fi復元、アプリ強制終了時の復帰保証は対応外または未検証。健康確認のキャッシュがある既存端末は再起動なしで新たなヘルス要求を送らない場合があるため、その間は待受表示を維持し、質問時のWebSocket接続でも到達を確認する。
