# 発話終了で送信する可変長録音

版: R04 / 更新: 2026-10-16（日本時間）。対象: COM4のM5AtomS3R + Atomic Voice Base A149、Gemini端末版R05。目的: 従来の3秒固定録音を可変長へ変更し、無発話では外部APIを呼ばない。

案件ルート: `C:\Users\thoma\SynologyDrive\H\Doc\Src\Codex\projects\ai-stackchan\AI_StackChan_Ex\Stackchan-chatgpt`

## 変更

- `include/UtteranceWindow.h` で既存SpeechGateを包み、20ms/320サンプル単位で判定。R03は開始直後400msを捨て、続く600msの環境音の90パーセンタイルRMSを測る。しきい値はmax(750,測定RMS×3)。3,000を超える環境ならNOISYで終了し送信しない。DC成分を除去し、累計発話200ms以上、末尾無音700msで終了する。
- 発話開始を約5秒待ち、無発話/短い物音だけなら端末内で終了する。直前200msを残して先頭無音を除き、送信PCMは最大80,000サンプル（5秒、前後の無音も含む）。実発話区間の上限4.8秒、到達時は途中でも区切る。
- `src/LocalGemini.cpp` はM5Unified0.2.26のsetBufferReleaseCallbackで、完了通知から次の録音先を予約する。要求間でDMAの残りを引き継ぎ、以前の逐次record→完了待ち方式の録音時間伸長を避ける。元の音声処理・ピン・マイク増幅・スピーカー音量は変更しない。
- 録音中の短押しはキャンセル。異常/無発話/キャンセル時は通信を開始しない。終了後はmic taskを停止してからバッファを切り出し、音声を消去する。
- protocol v2、1質問1回答、24kHz回答の受信/実再生完了通知は維持。PCサーバ/SDKの入力上限は既存5秒のまま。新しい認証情報やキー設定は不要。

## メモリ・依存・書込み

入力収集用の直線バッファ176,000サンプル/352,000Bと回答480,000BをPSRAMに固定確保。環境音測定1秒・発話開始待ちと最大発話を含めて収集し、完了通知のrelease/acquireで読書きを分離する。callbackはマイク終了や表示/ネットワーク処理を呼ばない。メイン側の壁時計上限12.5秒も設ける。可変発話長と連続ネットワーク送信は別で、現版は録音終了後にPCへ送る。

## 操作と残作業

起動方法は引き続き案件ルートのStart-Gemini-Device.cmd。画面ボタンをRelease to recordまで長押しして離し、開始音後のPreparing micでは約1秒静かに待ち、**Speak nowの表示が出てから発話**する。約0.7秒静かにすると送信する。何も話さなければNo speechで戻る。上限は送信音声全体5秒なので長い質問はまだ対象外。PCのstopまたは約10分でサービスを終了する。

開始時の環境音に合わせる方式で、発話中の雑音変化、距離・話速の調整や音質の定量評価は別途必要。会話履歴・ウェイク統合・連続ストリーミング・WSS/TLS・クラウド公開は今回の範囲に含まない。問題時は前の `gemini-device-r01.bin` をアプリ限定ツールで復帰する。
