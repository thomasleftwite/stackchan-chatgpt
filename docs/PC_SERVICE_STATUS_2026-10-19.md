# PCサービス停止後の接続表示

版: R02 / 2026-10-19（日本時間）。対象: AtomS3R + Atomic Voice Base A149 / Stage2 R01、Windows PC中継。目的: PC停止後もOnline表示が残る利用者報告を、正常停止通知と通知期限の経路に分けて確認する。

## 利用者報告と現行仕様

利用者が安定性確認の1（再生中の誤反応/中止/回答後の受付）と3（呼びかけの簡易評価）をOKと報告。個別の試行回数や誤検出率の数値は未取得。

2ではPCサービスを停止してもOnlineのままで、質問回答時にPC接続に失敗して表情が変わり、その後Start PC Service表示になった。その後、利用者からStart-Gemini-PC.cmdで起動/停止を評価し、質問せず20秒以上待ってもOnlineだったと回答あり。ウィンドウの具体的な終了操作は未取得。ユーザーの意図に基づき、追加原因追跡や常時監視の追加は行わず、次の問いかけ時の接続結果で利用不可表示へ変わる挙動を許容する。

LocalGemini.cppのpcReadyはconfigured/pcOnlineと、最後のUSB GEM PINGから20秒未満であることを判定する。質問時のLAN WebSocket接続成功を保証する表示ではない。GEM STOPは即座に接続設定を無効化する。GEM PINGが途絶えればloopで期限切れを処理し、操作なしでOffline表示と検出停止へ進む。現行Gemini UIホスト6項目は成功。

## 再現した欠落と修正

tools/run_gemini_device.pyはサーバ子プロセスが終了するとSessionFailure(server_exit)を投げ、USBコンテキストを閉じてから例外処理へ進んでいた。その経路にはGEM STOP送信がなく、正常な20秒期限までは端末に古いOnline表示が残り得る。同じ欠落がCtrl+CによるKeyboardInterruptにもあった。

tests/test_gemini_coordinator.pyの実mainを呼ぶ試験で、server_exit時に端末停止通知がないことをFAIL再現。修正後はシリアル接続を閉じる前の例外処理で、設定転送済み/未停止の場合に限り停止を試行する。USB切断中の停止エラーは元の失敗理由を上書きしない。Ctrl+Cは停止応答を確認できたとき正常終了する。強制プロセス終了やUSB切断では通知実行を保証せず、端末側期限が必要。

## 検証と限界

- python -m unittest discover -s tests -p test_gemini_coordinator.py -v: 16/16成功。新規2項目はサーバ終了/Ctrl+CでUSBクローズ前のSTOPと停止応答を確認。
- python tools/run_host_tests.py --suite gemini-ui: 既存6項目成功。通知期限後、追加ボタンなしのOffline表示、PING復帰/STOP後の受付禁止を確認。
- ファームウェア変更・書込みなし。実機で今回の停止方法と待ち時間を再現する試験は未実施。修正が今回報告の原因に一致するとは断定しない。
- USB接触不良の原因究明は利用者指示で保留のまま。この修正はPCサービス停止通知の独立した経路を扱う。

## 合意した扱い

利用者は「常時モニターするための無駄な通信を増やさず、次回問いかけ時にPCサービスの有無を確認する現行仕様で問題ない」と明示。PCのLANサービスへ常時監視を追加しない。Onlineは直近の状態表示として扱い、現在の回答サービスの疎通を保証しない。次の問いかけで接続できなければエラーを表示し、Start PC Serviceへ移る現状を許容仕様とする。20秒以上残った表示の根本原因が解明したこと、PC停止/復帰試験全体が合格したこととは区別する。

既存の5秒ごとのUSB GEM PINGと20秒期限はコードに存在し、今回削除や間隔変更はしていない。サーバ終了/Ctrl+C時のSTOP通知の修正も保持し、常時LAN監視を新設したものではない。今回の追記ではコード・端末・PCサービスの操作なし。

## 起動ファイルの区別

実機で会話するときはStart-Gemini-Device.cmdを使用する。このファイルはLAN接続先と一時トークンをUSBで端末RAMへ渡す。

今回利用者が評価に使ったStart-Gemini-PC.cmdはPC単独用。server/gemini-pc.tsはHOST未指定時127.0.0.1で起動し、COM4への設定転送やUSB稼働通知は行わない。したがって、この単独サービスの起動だけで端末が同じ接続先/トークンへ切り替わることは保証されない。今回の端末の不応答やOnline残留の直接原因と断定はしない。

USB接触不良の原因究明は引き続き保留。Stage2の1/3の基本動作確認は利用者報告として記録済み。PC停止表示について追加通信や修正を必須とする作業は終了する。
