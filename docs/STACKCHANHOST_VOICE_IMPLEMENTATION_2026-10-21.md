# StackchanHost 声選択・PC試聴 実装記録

2026-10-21 / R01 / 対象0.6.0-preview.1。目的: 恒常仕様の声選択と日本語サンプル試聴を実装し、未評価の声を通常リストへ混ぜずに評価・採用できるようにする。[仕様](STACKCHANHOST_VOICE_SPEC.md)と利用者の実装指示が基点。

## 今回の追加決定

利用者は「ホストだけ更新し、試聴時は端末をSleepingにする」を選択。ホスト単独では録音前の端末状態を取得できないため、試聴前に端末をSleepingにしてチェックを入れる操作を採用。Wi-Fiの待受は維持し、接続後の会話とPC試聴はホストで排他制御する。チェックは実機のSleep検知ではない。端末から新しい質問接続が届いたらチェックを解除し、試聴予約中なら受付を拒否して案内する。端末更新・USB監視は今回行わない。

## 実装した機能

- 主画面の「声（日本語・採用済み）」プルダウン、選択保存、次の質問からの反映。進行中の回答はセッション開始時の声に固定。
- 同じLiveモデルと明示的な声IDで共通の日本語サンプルを生成。PCの標準出力へ24kHz/16-bit/mono PCMをメモリから再生。「試聴を停止」で生成・再生を取り消す。起動や声選択だけではAPIを呼ばない。
- 「声を確認・管理」は通常の選択とは別の評価画面。PC試聴→指定声での端末質問・再生完了→利用者が日本語の品質を判断して採用、という手順。未確認/除外の声は通常プルダウンへ出ない。
- 対象モデルは現在gemini-3.8-live。評価候補はKore/Puck/Aoede/Charon/Fenrir/Zephyr。これは公式資料に基づく候補であり、日本語合格済み一覧ではない。自動採用はしない。モデルまたはカタログrevisionが変わった場合は再評価する。
- 採否理由、確認日（日本時間）、アプリ版、モデル、声ID、カタログ版、PC/端末確認をユーザー領域のvoice-reviews.jsonへ保存。APIキーや音声は含めない。壊れた記録は採用済みなしで起動し、再評価の保存前に原本を.invalid-UUIDへ保管。
- 声だけの保存では既存の暗号化APIキー・ネットワーク設定を保持。非対応声や失敗時に勝手な既定声へ変更しない。
- 待受中の声変更をNodeへ伝え、次セッションへ反映。試聴は生成からPC再生終了まで予約し、同時会話・二重試聴・試聴中のホスト開始を拒否。USB診断中の声評価は拒否しWi-Fi方式を案内。
- 話速/ピッチ調整は追加していない。発話前0.2秒ウェイトは別ToDoのまま。

## 依存と成果物

Windows 10/11 x64、Python3.14.4、Node24.15.0、PyInstaller6.22.3、@google/genai2.30.0。依存追加なし。PC音声再生はWindows標準のwaveOutを使用。UI/設定はdesktop/、カタログと中継はserver/。

配布先: `releases/StackchanHost-0.6.0-preview.1-win-x64/StackchanHost.exe`、53,339,281 bytes、SHA256 `9B4B803289B3F406E17AB20FD248264734B2213016C42EB0555CEAAE20BFF35F`。旧0.5.0-preview.1のSHA256 `881BF7649305218ED8854597BF22A3ECA97DFDE33FCBFD472F3ED27555F9FAA8`が不変であることを確認。コードと配布物の一致はbuild-manifest.json、EXEはSHA256SUMS.txtで確認する。端末ファームウェアは同梱しない。

## 検証

- Python全47件成功（既存39＋新規8）。声の採用条件、除外、版変更時の再評価、壊れた評価記録の保護、暗号化キー不変、PC音声の入力検証、取消時に音声出力を開かないこと、GUI選択・競合条件を確認。
- Node全37件成功（既存32＋新規5、TypeScript型検査を含む）。同じセッション内の声固定、次質問への変更、試聴予約と取消、無効声、Live接続の明示声指定、実際のWebSocket PCMプロトコルで再生完了通知/試聴中429を確認。
- 2軸の独立読取りレビューを実施。壊れた評価記録でアプリ起動不能、停止中の試聴とホスト開始の競合、USB評価の誤った声指定、採否理由の不足を修正し、再読取りで修正必須指摘なし。
- 全試験は模擬音声・代替Live接続・ループバックを使用し、API呼出し0、USBアクセス0。Windowsの実音声出力・声のAPI受理・日本語品質を証明するものではない。

空のstageからEXEを再生成し、公開候補1370ファイルの私有値一致0件。最終EXEの`--ui-self-test`は14項目PASS、apiCalls=0、終了コード0。声の候補・GUI・管理画面の配置、暗号化設定、模擬PCM通信、同梱Node/子workerを確認。記録`.pio/device-check/voice-host-060-self-test-r02.json`と配布先SELF_TEST.json。初回の自己診断ではTkのreadonly状態が文字列以外の型として返る比較によりvoiceUiだけFAILとなり、文字列化して再生成した最終版でPASSを確認した。

声を固定する時点はホストが質問接続を受け付けた時点。端末が接続前に録音している状態はホスト単独では取得できないため、声は質問操作の前に選択する。試聴時と同様、この限界を端末状態の自動検知があるようには案内しない。

## 残る確認

採用済みの声は現時点で0件。各声の日本語実聴、PC出力の再生/停止、実APIでの指定受理、端末での聞き取りやすさは利用者確認待ち。通常リストが空でも、評価画面からサンプルを聴いて候補を端末へ適用できる。再生完了通知は端末の状態証拠であり、日本語の品質の判定は利用者の採用操作を根拠とする。
